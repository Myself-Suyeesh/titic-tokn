## 1. What this project is

A small floating meter that shows, live, how many tokens (and roughly what cost) the prompt you are typing will use, updates when the reply finishes, and keeps a running estimate for the conversation. The MVP is a Manifest V3 Chrome extension for ChatGPT, Claude.ai and Gemini. It is free, open source, fully local and not a business.

Source documents: [`prd.md`](../prd.md) (requirements), [`design.md`](../design.md) (visual spec), `Tictic_Tokn_UI.html` (reference render of the design; open in a browser).

## 3. Decisions

| Decision | Choice | Why |
| --- | --- | --- |
| Build tooling | WXT 0.21 (Vite) | Generates the MV3 manifest, HMR, shadow-DOM content-script UI helper, easy Firefox build later |
| UI | React 19 + TypeScript 6 (strict) | Per PRD |
| Site order | ChatGPT, then Claude.ai, then Gemini | ChatGPT has an exact open tokenizer, so the first build is verifiable |
| Licence | MIT | Simple, permissive, compatible with OFL fonts and tokenizer libraries |
| Delivery | PRD milestones 1-4, one branch each, stop after each for approval; the maintainer pushes and merges | Small reviewable steps |
| Counting | Exact for OpenAI-style models; ratio-based estimate for Claude and Gemini | No public tokenizer for those; ratios live in a data file |
| Tokenizer library | `gpt-tokenizer` 4 with the `o200k_base` encoding | Pure JS, offline. The library has a file per model and uses `o200k_base` for GPT-4o, GPT-4.1, the o-series and GPT-5 up to 5.6 Sol/Terra/Luna. |
| Exact versus est. | A model is **exact** only if the library lists that model; otherwise it is counted with `o200k_base` but labelled **est.** | GPT-6 (all variants) and plain GPT-5.6 are not in the library, so their tokenizer is unverified. `scripts/update-prices.mjs` sets the flag automatically. |
| Fonts | `@fontsource` packages (Inter 400/500, Space Grotesk 600, latin subset) | OFL licence notices ship with the packages |
| Prompt selector (ChatGPT) | `[data-composer-input] [contenteditable="true"][role="textbox"]`, fallback `#prompt-textarea` | ChatGPT's composer is a ProseMirror editor; class names are hashed and unstable |
| Price data | Curated subset of the open LiteLLM table in `data/model-prices.json`, regenerated by `scripts/update-prices.mjs` | The full table is 3.5 MB; the extension itself never touches the network |
| Model on ChatGPT | The user picks it; the choice is saved per site in `chrome.storage.local` | The free plan shows no model name on the page |
| Permissions | `storage` only | Needed to remember the model per site |
| Long chats | Remember each message's token count by id (in memory, per page load) and show "N messages not loaded" for ones never seen | ChatGPT keeps tall empty spacers for off-screen messages in very long chats, so their text is not in the page. Scrolling through the chat once fills the memory. |
| Reply finished | The conversation is recounted once the page has been still for 1 second (`QUIET_MS`), not by detecting a Stop button | Works on every site and language; a pause mid-reply only causes an extra, harmless recount |
| Conversation reading | Only while status is Tracking; text held in memory only | Same privacy rule as the prompt: nothing is read unless the prompt box has focus and capture is on |
| Estimate engine for Claude and Gemini | Moved into the adapter branches 3b and 3c | Model labels and names can only be verified against those sites' real pages |
| Tracking states | Priority Paused, Ignoring, Not tracking, Tracking; only Tracking reads the page | Privacy: nothing is read unless the prompt box has focus and capture is on |
| Trim hint target | The amber threshold (70%) | Fixes the contradictory copy in the first design |
| Network | None for user content | Local-only privacy promise |

Open questions still in the PRD (§18): standalone-app OS, final name and domain, extra day-one sites, how sites expose long conversations, Claude Code log format, token-count API terms, terminal capture rule, publishing route.

## 4. Architecture

```
Page (chatgpt.com)
  └─ content script (entrypoints/content.tsx, WXT) → shadow-DOM React app (components/App.tsx)
       ├─ useFocusState     → focus in prompt box / in a secure field / elsewhere
       ├─ getTrackingState  → Paused | Ignoring | Not tracking | Tracking
       ├─ usePromptText     → watchPrompt reads the prompt box ONLY while Tracking
       ├─ useModel          → page label (adapter) or the saved choice (chrome.storage.local)
       ├─ useConversation   → watchConversation reads the visible messages ONLY while Tracking,
       │                      after the page has been quiet for 1 s (a finished reply)
       ├─ countConversation → history tokens, counted when messages or model change (not per keystroke);
       │                      a per-message token cache (memory only) covers messages the site unloaded
       ├─ countFor + buildReadout → prompt tokens, context = history + prompt, exact/est., cost,
       │                      % of window, level, trim hint, latest reply cost
       └─ FloatingShell → Card (chip, count, unit line, meter, footer, status line) or Pill
```

**Data flow:** focus decides whether capture is live → the adapter's prompt text and visible messages → `countFor` / `countConversation` (exact with the model's tokenizer, or the generic ~4 chars/token estimate when no model is known) → `buildReadout` adds the context total, cost and context share from the price table → the card renders. The big number is the prompt; the bar, percentage, hint and cost use prompt + visible history.

**Layout**

| Path | Purpose |
| --- | --- |
| `entrypoints/content.tsx` | Content script: picks the adapter, mounts the app in a shadow root |
| `components/` | `App`, `Card`, `Pill`, `FloatingShell` (drag and tap), `Meter`, `StatusLine`, `ModelChip`, `ModelPicker`, `icons`, `Card.css` |

### SiteAdapter contract
Built: `id`, `name`, `modelFamily`, `matches(url)`, `getPromptElement(doc)`, `readPromptText(el)`, `getModelLabel(doc)`, `getConversationRoot(doc)`, `getMessages(doc)`. Adapters read only the prompt box, the model label and the message text elements. On ChatGPT a `[data-turn-key]` turn holds both the user's message (`[data-user-message-bubble]`) and the reply (`[data-markdown-text-style="assistant-message"]`, excluding muted `data-markdown-text-tone="tertiary"` blocks); the hidden role headings and action buttons in a turn must never be counted, so only those two elements are read. Each message has a stable id (`turn key : role : index`); empty text means the site has not loaded it.

## 5. Behaviour rules

- Numbers are labelled **exact** or **est.**; the cost footer's tooltip says "API-equivalent estimate, excludes hidden thinking and system prompt".
- The big number is the prompt being typed. The "In context ~N · visible conversation only" line shows prompt plus visible history; the bar, percentage, trim hint and cost use that total.
- Context colour: green below 70%, amber from 70%, red from 90%. The number, the meter and the unit line change; the meter's segments also widen (2, 3, 4 px) and the pill marker changes shape (circle, triangle, square).
- Four status states only: Tracking, Paused, Not tracking, Ignoring. Outside Tracking the number and meter dim to 40%, the unit line reads "last count · not live", and the footer stays at full strength.
- Not tracking means focus is outside the prompt box. Pausing, or focusing a password or payment field, also stops all reading.
- Performance target: count updates within 100 ms for prompts up to 10k tokens. Measured tokenizing time in Node: about 0.6 ms for 10k simple tokens, about 6 ms for 16k mixed-unicode tokens, so no worker is needed.
- A finished reply updates the total about one second after the page stops changing. A 100k-token recount takes roughly 30 ms.
- Idle CPU under 1%: the watcher observes only the prompt box and polls one cheap `querySelector` every 500 ms (only while tracking); the model label is read once a second. *(not measured yet)*

## 7. Known limits

- Only chatgpt.com is supported (free plan tested, home screen and open conversation).
- **Long chats on ChatGPT unload off-screen messages.** In a very long conversation (tens of thousands of pixels tall) most reply containers are empty spacers, so only a few messages are readable at once. The extension remembers each message's count the first time it is loaded and keeps using it after it unloads, and the card shows "~N+ · M messages not loaded" for messages never seen. Scroll through the chat once to include them. Counts are lost on page reload. This was found when a huge chat showed ~51 and a short one ~410.
- **The conversation total is a floor**: it counts only visible message text, not per-message overhead, hidden reasoning, system prompts or attachments, and long chats may unload old turns. The label says "visible conversation only".
- **The total updates only while the prompt box has focus** (status Tracking). Open an existing conversation and the "In context" line appears after you click into the prompt box. While status is Not tracking (for example right after clicking New chat, before you click into the box) the card keeps showing the last values; the "In context" line is not dimmed in that state (decision), so it can look live until you click into the box.
- **Long pastes become attachments.** ChatGPT turns very long pasted text into an attachment chip instead of text in the prompt box. The extension reads only the prompt box, so attached text is **not counted**. Handling attachments is not planned yet.
- **GPT-6 and GPT-5.6 (plain) read "est."**: counted with `o200k_base` as an approximation because the tokenizer library does not list them. They turn to exact when the library adds them (re-run the price script after upgrading it).
- **Which GPT-6 variant?** ChatGPT's apps say "GPT-6" but the price table only has variants (Sol, Luna, Astra, and 6.1 Sol/Terra) with very different prices ($0.1 to $10 per million input tokens). The picker lists the variants; the user chooses. A model's own answer about what it is is not a reliable source.
- **Before a model is picked** the count is a generic estimate (~4 characters per token), labelled "Pick a model · est.", with no cost or context share.
- The context percentage uses the model's **API** context window from the price table. ChatGPT's own apps can limit conversations to less, so the percentage is a guide, not the app's real limit.
- Prices are a snapshot (see `snapshot` in `data/model-prices.json`). Long-context tiers, caching and batch discounts are ignored. Editing prices arrives with the options page in Milestone 4.
- The picker offers 21 OpenAI-family models, newest first (the list scrolls); Claude and Gemini arrive with their adapters in Milestone 3.
- Pause and collapse are not remembered across page reloads (only the model choice is stored).
- The bundle is about 2.5 MB (mostly the `o200k_base` vocabulary and embedded fonts). Fine for a sideloaded build.
- Fonts are embedded as data URIs; if a site's content security policy blocks them, the card falls back to the system font.
- 9 moderate `npm audit` findings exist in dev-time build tooling (a `minimatch` range). Production dependencies report 0.
- Tokenizer parity is checked against one known value ("Hello world" = 2). A larger fixed test set is planned for Milestone 4.
- No automated UI (component) tests yet; logic is covered in `core/` and `lib/`, and the UI is checked manually.

## 8. How to build and verify

```bash
npm install
npm run check          # typecheck, lint, tests, build (104 tests)
```

Then in Chrome: `chrome://extensions` → **Developer mode** → **Load unpacked** → select `.output/chrome-mv3` (click the reload icon on the extension after each build; the manifest gained the `storage` permission in Milestone 2).

### Milestone 3a: ChatGPT conversation total and reply update (10 Nov 2026)
- Split Milestone 3 into three branches by decision: 3a (this one), 3b Claude.ai, 3c Gemini. The estimate engine and Claude and Gemini model data moved into 3b and 3c.
- Page structure was taken from real DOM probes of chatgpt.com. Two of my early guesses were wrong (`[data-message-author-role]` and `data-testid="stop-button"` match nothing today), so the adapter uses `[data-turn-key]`, `[data-user-message-bubble]` and `[data-markdown-text-style="assistant-message"]`, with tests built from the real shape including hidden headings and buttons that must not be counted.
- New: `getConversationRoot` and `getMessages` on the adapter, `watchConversation` (recount after 1 s of quiet), `countConversation`, `buildReadout` with a history, `estimateOutputCost`, the "In context" line and the cost tooltip. `design.md` was updated first.
- 104 unit tests (up from 71).
- Verified manually in Chrome on chatgpt.com (free plan): the "In context" line and its number, the update after a reply, the cost tooltip, switching between chats including New chat, and the long chat ("~N+ · M messages not loaded", growing as you scroll). All passed after the fixes below.
- **Stale conversation after switching chats, found in manual testing:** the number stayed at the previous chat's value until a reload. A probe showed two conversation elements in the page, the old one hidden (height 0) and first in the document, so the adapter read the wrong one. The adapter now reads only a visible conversation (the newest if several). A first version of this fix fell back to the newest hidden conversation when none was visible, which made a new chat show the previous chat's total (629); hidden conversations are now never read, so a new chat has no "In context" line. This should have been covered together with the prompt-box fix; it now has three tests.
- **Stale count after leaving the prompt box, found in manual testing:** going from some chats to a new chat kept showing the old chat's "In context" value. A probe showed the old conversations were all `display: none` and correctly ignored, so the cause was state: the conversation watcher is switched off when focus leaves the prompt box, and the next one started with "nothing changed" memory and skipped its first read when no conversation was visible, so the card kept the old messages. The watcher now always does a first read and reports it, even when empty. Two tests cover it.
- **Long-chat fix, found in manual testing:** a very long chat showed ~51 while a short one showed ~410. Probes showed ChatGPT keeps empty tall spacers for off-screen messages (virtualization), and that turns can contain several reply-style elements, some of them empty muted blocks. Fixes: messages get stable ids, muted blocks are skipped, token counts are remembered per message (memory only), and the card says how many messages are not loaded. My first diagnosis (placeholders that fill on scroll) was based on a probe that read the wrong element; the structure probe corrected it.
